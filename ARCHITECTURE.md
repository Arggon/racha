# racha — Architecture

## Problem

Las apps de hábitos son subscriptions con nube. `racha` es un tracker de
hábitos con rachas que corre 100% local: un binario CLI en Rust, un ledger
JSON legible en el directorio de datos XDG, y nada más. Para quién: usuarios
de terminal (y agentes) que quieren registrar un hábito en dos palabras y
consultar su racha en un comando. Objetivos duros: offline-first, datos
portables (backup = `cp`), arrastre < 50 ms para poder correr desde un timer
de systemd.

Non-goals: sincronización multi-dispositivo, UI de escritura (la web del
roadmap es de solo lectura), métricas sociales, cuentas de usuario.

## Big picture

Flujo de `racha check meditar`:

1. `main.rs` parsea el subcomando con clap (derive) y resuelve el directorio
   de datos (flag `--data-dir` > env `RACHA_DATA_DIR` > XDG).
2. `storage::load` lee `ledger.json` (ausente = ledger vacío válido).
3. `model::Ledger::habit_mut` encuentra el hábito y `Habit::add_check`
   agrega la fecha local de hoy (idempotente: un check por día).
4. `storage::save` reescribe el ledger entero (pretty JSON + `\n` final).
5. `streaks::*` computa racha actual / mejor racha / vista semanal y
   `print_habit` renderiza.

Dirección de dependencias: `main → storage → model` y `main → streaks →
model`. `streaks` es puro (fechas in, enteros out) y no toca I/O.

## Code map

```text
racha/
  src/
    main.rs      # CLI (clap): parseo, I/O de usuario, orquestación
    lib.rs       # raíz de lib para tests y consumidores externos
    model.rs     # Habit + Ledger: identidad, checks, unicidad de nombre
    storage.rs   # carga/persistencia del ledger JSON; resolución de paths
    streaks.rs   # motor puro: current/best streak, week_view
  tests/
    cli.rs       # integración: el binario real vía assert_cmd
  docs/          # FORMAT.md (ledger), DECISIONS.md, convention/engineering,
                 # adr/, explorations/, playbooks/, runbooks/, specs/
  tasks/         # work items arggon (fuente de verdad del trabajo)
  templates/     # plantillas de work items
```

Nada de I/O ni de presentación en `model`/`streaks`; nada de lógica de rachas
en `main`/`storage`.

## Boundaries and layering rules

- `streaks` no importa `storage` ni hace I/O: funciones puras de `&[NaiveDate]`.
- Toda escritura del ledger pasa por `storage::save` (nunca `fs::write` suelto).
- Las fechas que se persisten son siempre locales (`Local::now().date_naive()`),
  formato ISO `YYYY-MM-DD` — ver docs/FORMAT.md.
- Errores de negocio son `String` legible en español con exit code 1; los de
  storage nombran el archivo y la causa.

## Invariants

- Un check por hábito por día (idempotencia) → `double_check_is_idempotent`
  (tests/cli.rs) + `Habit::add_check` devuelve `false` si ya estaba.
- Nombres de hábito únicos → `duplicate_add_fails` (tests/cli.rs).
- Ledger ausente nunca es error; ledger corrupto nunca se sobreescribe →
  `missing_ledger_is_empty` + mensaje "ledger corrupto" en `storage::load`.
- La racha actual no se rompe hasta medianoche si ayer hubo check →
  `current_streak_survives_until_midnight_when_today_missing`.
